# Асинхронная загрузка текстур

## Запуск

Собрать `Try2.sln`, Debug x64. В меню Scenes выбрать **Texture Streaming (1000 Textures)**.
Тестовые файлы уже сгенерированы в текущем workspace. На другом компьютере сначала выполнить из корня:

```powershell
python tests/GenerateTextureStressScene.py
```

Скрипт создаёт 1000 разных DDS 64×64 и сцену с 1000 кубами. Сгенерированные файлы исключены из Git.
Очереди, ошибки, память и время загрузки видны в Statistics. Для повторной загрузки переключиться на другую сцену и вернуться.

## Поток данных

`ResourceManager::LoadTexture` возвращает стабильный ID и ставит запрос в очередь.
Путь нормализуется; ключ кэша включает цветовое пространство. По умолчанию сохраняется формат файла,
для normal maps используется Linear. Можно явно запросить SRGB.

`Queued → LoadingCPU → ReadyCPU → UploadingGPU → Ready`.
Также существуют `Failed` и `Cancelled`; текст ошибки доступен через `GetTexture(id).error`.

- `JobSystem` скрывает enkiTS и содержит отдельные CPU/Loading scheduler.
- Чтение и подготовка DDS, декодирование PNG/JPEG через WIC выполняются в Loading.
- Loading использует pinned jobs на рабочих потоках: чтение не выполняется вызывающим потоком.
- Рендер забирает подготовленные данные в BeginFrame и копирует текстуры полосами через direct queue.
- EndFrame назначает реальный fence. Готовность публикуется после его завершения.
- До готовности материал использует белую текстуру / плоскую normal map; ошибка albedo — пурпурная текстура.
- Upload-буферы, отменённые GPU-ресурсы и их дескрипторы освобождаются только после fence.
- При смене сцены отменяются текстуры, которых нет в материалах новой сцены. ID мешей и материалов
  сохраняются для существующего формата Play-снимков; отменённые текстуры можно загрузить снова.

## Лимиты

Настройки GPU находятся в `TextureUploader::Limits`:

| Ограничение | По умолчанию |
| --- | --- |
| Loading workers | 2 |
| Одновременно удерживаемые CPU-загрузки | 4 |
| Файл / подготовленные данные одной загрузки | до 64 MiB |
| Резерв CPU-данных | до 256 MiB |
| Копирование за кадр, включая row padding | 8 MiB |
| Время pump | мягкий предел 2 ms между операциями |
| Начало GPU-загрузок за кадр | 4 |
| Незавершённые upload-буферы | 64 MiB |
| GPU-память загруженных текстур | 512 MiB |

CPU-резерв ограничивает собственные файловые/декодированные буферы, а не всю память процесса или внутренние
аллокации WIC. GPU-лимит относится к потоковым текстурам, не включает меши, render targets и три fallback-текстуры.
При превышении GPU-памяти или числа дескрипторов запрос завершается ошибкой. Автоматического LRU-вытеснения нет.
Диапазоны общей кучи: 0–899 для остальных engine views, 900–963 для ImGui, 1024–8191 для загрузчика.

## JobSystem API

Все вызовы API выполняются в потоке, вызвавшем Init; worker callbacks работают со своими данными.

```cpp
auto& jobs = JobSystem::Get();
jobs.Init();
auto job = jobs.Submit([result] { result->Prepare(); }, JobSystem::Queue::Loading);
// В следующих кадрах:
if (jobs.IsComplete(job)) {
    jobs.Wait(job); // Здесь уже не блокирует; пробрасывает исключение callback.
    Consume(*result);
}
```

`Queue::CPU` предназначена для вычислений. Такие задачи enkiTS может выполнять и в вызывающем потоке.
Система удерживает задачи до их фактического завершения, даже если вызывающий код отпустил Handle.
Shutdown дожидается workers. Отмена загрузок кооперативная: уже выполняющийся WIC decode или системное чтение
может закончиться перед завершением shutdown. Доступ к ECS, материалам и DX12 из callbacks не нужен.

## Проверка

```powershell
pwsh -File tests/RunTextureStreamingTests.ps1
pwsh -File tests/RunPhysicsTests.ps1
```

Тест загрузчика использует DX12 WARP и debug layer при наличии. Проверяет время жизни jobs, исключения,
дедупликацию, лимиты, readback пикселей/BC1/mip levels/PNG, повреждённые файлы, отмену и перезапуск,
освобождение дескрипторов и 1000 уникальных текстур. Печатает собственные измерения.

Первый прогон: 1000 DDS 64×64 с прогретым файловым кэшем — синхронное CPU-чтение/подготовка 46.35 ms;
постановка запросов 40.81 ms; GPU pump p95 1.28 ms, максимум 1.97 ms. Полная загрузка в тестовом цикле —
7.76 s / 501 кадр, включая искусственное ожидание между кадрами. Это проверка распределения работы,
не сравнение FPS и не обещание ускорения общей загрузки. Повторный прогон с проверкой PNG: p95 1.32 ms,
максимум 7.23 ms — отдельный вызов драйвера может превысить мягкий предел 2 ms.
Создание запросов и поиск путей пока синхронны.

Текущая реализация загружает 2D DDS с готовыми mip levels и изображения WIC с одним mip level.
Меши/Assimp и разбор JSON остаются синхронными. Мипы WIC автоматически не генерируются;
для игровых ассетов предпочтительны заранее подготовленные DDS.
